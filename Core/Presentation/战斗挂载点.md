# 战斗挂载点总表（本体可挂点 ↔ 我们挂了什么）

> 2026-10-15 整理。**改位置/改挂点的唯一入口见每行"调参"列**；本体节点名以 `orign/src` 反编译源码为准
> （场景里的 `%UniqueName` 与属性名一一对应）。

## 1. 本体战斗的节点树（可挂载点）

```
NCombatRoom                                   ← 战斗房间根（我们的补丁打在它的 _Ready 上）
├─ %CombatSceneContainer  (= Room.SceneContainer)   ZIndex = -10（整棵子树都在 UI 之下）
│  ├─ %BgContainer            战斗背景                       ← 我们把「领域」层插到它后面（index 1）
│  ├─ %BackCombatVfxContainer 背景层特效
│  ├─ %AllyContainer          我方角色节点（每个 NCreature 一棵）
│  ├─ %EnemyContainer         敌方角色节点
│  └─ %CombatVfxContainer     战斗特效容器                   ZIndex = -9
├─ Ui (= NCombatUi)
│  ├─ %EnergyCounterContainer 能量计数器容器（本体默认位置 (100, 806)）
│  │   └─ NEnergyCounter（本体按 CharacterModel.EnergyCounterPath 实例化场景）
│  ├─ %StarCounter            星星计数
│  ├─ %EndTurnButton          结束回合按钮
│  ├─ %PingButton             标记按钮
│  ├─ %CombatPileContainer    牌堆按钮容器
│  │   ├─ %DrawPile           抽牌堆按钮（我们的意图卡带小卡会读它）
│  │   ├─ %DiscardPile        弃牌堆按钮
│  │   └─ %ExhaustPile        消耗堆按钮
│  ├─ %Hand (NPlayerHand)      手牌
│  ├─ %PlayContainer          出牌动画容器
│  ├─ %PlayQueue              出牌队列
│  ├─ %CardPreviewContainer / %MessyCardPreviewContainer   预览容器
│  └─ （RitsuLib 追加）NModExtraHand 等额外手牌容器           ZIndex = -1
└─ CreatureNodes（每个 NCreature 一棵：Hitbox / Visuals / IntentContainer …）
```

顶栏（不在战斗房间子树里）：`NRun` 下的 top bar —— 本体「卡组」按钮、遗物栏，以及 RitsuLib 按
`Style = TopBarDeck` 给我们加的牌堆按钮（`Anchor = TopBarAfterDeck` / `TopBarBeforeModifiers`）。

## 3. 定位与绘制序要点（改位置前先看这几条）

1. **按键行不是固定坐标**：每帧按 `能量球.GlobalPosition + (XOffset, 球高 + GapBelowCounter)` 跟随能量计数器，
   连球的进出场动画也跟（0.6s Expo-out / Back-in）。所以要"往上/往下"就改 `GapBelowCounter`（负得越多越靠上），
   左右改 `XOffset`；**改挂点不会改变它的位置**（挂点只决定生命周期与点击层级）。
2. **`%CombatSceneContainer` 整棵子树 `ZIndex = -10`**，所以「领域」层插 index 1 就天然在背景之上、人物之下；
   想让它盖住人物要显式给 `ZIndex`。
3. **层级现状（2026-10-15 调整后）**：按键行 = `NCombatUi` 的普通子节点、插在**回合按键之前**（`ZIndex = 0`，
   所以画在能量计数器之上、回合按键与之后那些兄弟之下）；~~控制面板 = 214（房间根）~~（2026-10-16 已删，214 这个槽位空出来了）；意图卡带调度器 = `%EnemyContainer` 下、
   不画东西；额外手牌容器 = -1；传送门 = `%CombatVfxContainer` 下 `-1`（在世界空间里，人物会盖住它、屏幕震动带着它晃）。
   ⚠️ 按键行回到 `ZIndex = 0` 后，**与牌堆按钮 / 手牌 / 预览容器重叠的地方点击仍会被它们吃掉**（历史踩过）；
   它现在贴在计数器正下方、体积小，正常不重叠 —— 哪天点不动了先看这里。
4. **顶栏不归战斗房间管**：搁浅 / 第二副牌组的按钮是 RitsuLib 按 `TopBarDeck` 样式加的，位置由锚点
   （`TopBarAfterDeck` / `TopBarBeforeModifiers`）决定，改它们别去 CombatSceneContainer 找。
   ⚠️ **z 是沿父链累加的**（本体没关 `z_as_relative`）：`CombatSceneContainer = -10` 之下，
   `BgContainer / BackCombatVfxContainer / AllyContainer / EnemyContainer` 都是 0（相对）⇒ 有效 **-10**；
   而 `CombatVfxContainer` 是 -9（相对）⇒ 有效 **≈ -19**（比背景和人物都低）。所以要"门在人物之后、又别被背景盖住"，
   应挂 `%BackCombatVfxContainer`（-10，与人物同层、树序在前）；挂 `%CombatVfxContainer`（-19）有可能整道门被背景吃掉。
   切换只需改 `AeonglassGapPortals.SceneLayer`（`CombatVfx` / `BackCombatVfx`）；进战斗时 log 里那行
   `[间隙] 场景分层：…` 是实测值，照它判断。
5. 找不到父节点时的表现与日志：领域层 → `[HOST] 找不到 CombatSceneContainer ⇒「领域」层没挂上。`；
   按键行 → `[间隙] 找不到「回合按键」⇒ … 退到最后一个子节点`（层级会偏高）/ `找不到能量计数器（NEnergyCounter）⇒ … 暂不显示`；
   传送门 → 静默跳过（机制照常）。
